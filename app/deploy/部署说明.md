# 小金库 · 自建服务器同步部署说明

把应用在手机和电脑之间打通：数据存在你自己的服务器上，两端自动同步。

---

## 一、服务端准备（宝塔）

### 1. 建站点
- 宝塔 → 网站 → 添加站点
- 类型选**纯静态**（不需要数据库、不需要 PHP 版本选择以外的东西）
- 域名建议用子域名，例如 `money.example.com`
- 根目录例如 `/www/wwwroot/money.example.com`

### 2. 申请 HTTPS（必做）
- 站点设置 → SSL → Let's Encrypt → 申请并开启**强制 HTTPS**
- 原因：手机「添加到主屏幕」、剪贴板等能力都要求 HTTPS；同时避免明文传输财务数据。

### 3. 上传同步接口
在站点根目录下建一个 `sync` 目录，把本文件同目录下的两个文件放进去：

```
/www/wwwroot/money.example.com/sync/api.php
/www/wwwroot/money.example.com/sync/.htaccess   （见下文，用于保护 data 目录）
```

然后把 `api.php` 上传到 `/sync/api.php`。

### 4. 创建数据目录与令牌
**推荐做法（数据放在站点外，最安全）**：

编辑 `api.php` 顶部这一行，把数据目录指到站点之外：

```php
const DATA_DIR = '/www/backup/xiaojinku-sync';
```

然后 SSH 或宝塔文件管理器执行：

```bash
mkdir -p /www/backup/xiaojinku-sync/history
# 写入你自己的令牌（一行，建议 20 位以上随机字符）
echo '你的自定义令牌' > /www/backup/xiaojinku-sync/token.txt
chmod 700 /www/backup/xiaojinku-sync
chmod 600 /www/backup/xiaojinku-sync/token.txt
```

**简化做法**：数据放在站点内 `sync/data`（脚本会自动建目录并写入保护文件），
仍需创建 `sync/data/token.txt` 写入令牌。站点内目录**必须**配合下面的 `.htaccess`。

### 5. 保护数据目录
若数据目录在站点内，在 `sync/data/.htaccess` 写入（脚本首次运行会自动创建）：

```
Require all denied
```

Nginx 用户请在站点的 Nginx 配置里加：

```nginx
location ~* ^/sync/data/ {
    deny all;
}
```

### 6. 建议加一层访问密码（可选）
宝塔 → 站点设置 → 目录保护 → 对 `/sync` 开启 Basic Auth。
虽然数据不在服务器上，但没必要让财务应用接口裸奔在公网被扫描。

---

## 二、应用内配置

1. 把 `dist/` 目录下的全部文件（`index.html`、`manifest.webmanifest`、`sw.js`、`icons/`）上传到站点根目录（保持目录结构，`index.html` 在根目录即可直接访问域名打开）。
2. 打开应用 → 设置 → **云同步**：
   - 接口地址：`https://money.example.com/sync/api.php`
   - 访问令牌：上一步 token.txt 里的那串字符
   - 打开「启用云同步」
3. 点「立即上传」，把当前数据作为初始版本推到服务器。
4. 在另一台设备（手机）打开同一地址，填同样的地址与令牌，点「立即下载」。

---

## 三、同步行为说明

- **本地优先**：数据先写本机 IndexedDB，离线照样记账，联网后再同步。
- **自动推送**：任何改动后约 2 秒自动上传（防抖，连续记账只推一次）。
- **自动拉取**：每次打开应用时自动拉取服务器数据。
- **冲突处理（重要）**：
  如果服务器上的数据比你这台设备已同步的版本更新，**不会静默覆盖**。
  应用会弹窗让你选择：
  - 「用服务器的」：本机数据被服务器数据替换
  - 「保留我的并覆盖服务器」：以本机为准，强制上传
  
  这样手机和电脑同时改了数据，也不会有一边的记录凭空消失。

- **历史快照**：服务端每天保留一份快照，最多 30 份（在 `history` 目录），误删可从中恢复。

## 四、常见问题

**Q：换了域名/从本地预览切到服务器后，数据不见了？**
这是正常的——浏览器数据按「协议+域名+端口」隔离。
正确顺序：先在原地址**导出 JSON** → 部署到新地址 → **导入 JSON**。

**Q：同步失败怎么办？**
依次检查：① 接口地址是否以 `https://` 开头且可访问；② 令牌是否与 token.txt 完全一致（注意别带换行）；
③ 服务器是否开了 HTTPS 且证书有效；④ 浏览器控制台是否有 CORS 报错（若报 CORS，说明 api.php 的 CORS 头没生效，检查 PHP 是否正常解析该文件）。

**Q：数据存在服务器上安全吗？**
数据以明文 JSON 存在你自己的服务器，不经过任何第三方。
传输走 HTTPS。配合目录保护 + 强令牌，对自用场景足够。
若特别在意，可在服务器上对数据目录做磁盘加密。

**Q：同步后还需要导出备份吗？**
建议保留。服务器硬盘也会坏，两边都留最稳。
应用会在概览页提示你超过 30 天未备份。

## 五、性能：加载慢 / 更新不生效（v2.26 起必读）

前端自 v2.26 起是**「秒开 + 后台更新」**模式：打开时直接用本地缓存渲染，同时后台偷偷下载新版，
下次打开（或点提示条刷新）才是新版。因此有两件事必须在服务器侧配合。

### 1）`sw.js` 必须不被缓存（必做）

`sw.js` 是 Service Worker 本体。它被 CDN 缓存的话，**新版前端推不下去**——用户最多要等缓存过期才更新。
实测你的站点 `sw.js` 被缓存了 12 小时（`Cache-Control: max-age=43200`）。

宝塔 → 网站 → 设置 → **配置文件**，在 `server { ... }` 内粘贴：

```nginx
# ===== 小金库 · Service Worker 绝不缓存（否则新版前端推不下去）=====
location = /sw.js {
    add_header Cache-Control "no-cache, no-store, must-revalidate" always;
}
```

保存后（面板会自动重载 nginx）。若手改文件：`nginx -t && nginx -s reload`。

改完**还要去 Cloudflare 清一次缓存**（旧文件可能已经在边缘节点上）：
`Cloudflare 后台 → 缓存 → 配置 → 清除缓存（全部）`。
不清的话，边缘缓存要等原 12 小时过期才回源拿新头。

### 2）同步接口绝不能被缓存（不要动）

`/sync/api.php` 是账本同步接口，**一旦被缓存就会永远拉不到新数据**。
默认它是 `DYNAMIC`（不缓存），保持即可。不要为了"提速"给它加任何缓存规则。

### 3）首页短缓存（可选）

做了「秒开」之后，日常打开根本不走网络，所以这条收益有限，可不做。
想减轻回源压力可加（5 分钟）：

```nginx
location = /index.html {
    add_header Cache-Control "public, max-age=300" always;
}
```

### 4）验证是否生效

```bash
curl -sI https://你的域名/sw.js | grep -i cache-control    # 应含 no-cache
curl -sI https://你的域名/sync/api.php | grep -i cf-cache-status   # 应为 DYNAMIC
```

### 5）体积参考

单文件 `index.html` 约 825 KB，brotli 压缩后 **约 227 KB**（v2.26 把 ECharts 改为按需引入，
比原来的 445 KB 少了一半）。首次安装仍需下载一次，之后都是本地缓存秒开。

## 六、安全加固（v2.28 起，必读）

### 1）令牌与 PIN 不再进入备份与同步载荷

导出 JSON、上传到服务器的快照**只包含账本数据**（负债 / 分类 / 流水 / 证券 / 投资交易 +
账本级设置）。以下**设备本地配置永不出域**：

`sync`（含令牌）、`pinHash`、`appLockEnabled`、`theme`、`lastBackupAt`、`dividendScanAt`

- 导入他人备份 / 从服务器拉取数据时，这些字段**一律以本机值为准**，不会被覆盖
  （否则导入一份他设备的备份会把同步地址改掉、甚至用陌生 PIN 把人锁在门外）
- 服务端 `api.php` 在写入前会**再剥离一次**这些字段，旧版客户端上传也存不进去

### 2）新增文件锁，需要目录可写

`api.php` 现在用 `DATA_DIR/.lock` 把「读 → 版本判定 → 写」整个临界区锁住，
避免两个并发请求读到同一版本、都通过冲突检查、后写的无声覆盖先写的。

请确保数据目录**对 PHP 进程可写**（脚本会自动建 `.lock` 文件）：

```bash
# 站点内：改属主为 www；站点外：按你的 PHP 运行用户调整
chown -R www:www /www/wwwroot/你的域名/sync/data
```

临时文件也改成唯一名（`xiaojinku.json.tmp.<pid>.<随机>`），不再并发互踩。

### 3）CORS 白名单

`api.php` 顶部 `ALLOWED_ORIGINS` 只放行白名单来源，不再回显 `Access-Control-Allow-Origin: *`。
**如果你换了域名或用别的地址访问，必须把它加进这个数组**，否则浏览器会拦掉请求：

```php
const ALLOWED_ORIGINS = [
    'https://xiaojinku.19950920.xyz',
    'http://localhost:5173',   // 本地联调用
    ...
];
```

另：`?token=` 查询参数传令牌的通道已移除（令牌会进访问日志），只用 `X-Sync-Token` 头。

### 4）数据文件损坏的处理变了

以前 JSON 解析失败会被当成「空账本」（version 0），导致版本号回退、冲突检测失效。现在：

- GET 遇到损坏 → 返回 **500**，不返回 version 0
- POST 遇到损坏 → 拒绝写入（保护现场）；确需恢复时客户端用「强制覆盖」，
  服务端会先把损坏文件隔离成 `corrupt-<时间>.json` 再重建

### 5）令牌轮换（建议做一次，尤其如果你曾用旧版同步过）

改代码**不会**清理已经躺在服务器数据文件和历史快照里的旧明文令牌。
轮换才让它们失效：

```bash
# 1）生成新令牌
openssl rand -hex 24

# 2）写入 token.txt（替换旧值）
echo '新令牌' > <DATA_DIR>/token.txt

# 3）清理含旧令牌的历史快照
rm -f <DATA_DIR>/history/snapshot-*.json

# 4）各设备：设置 → 云同步 → 填入新令牌 → 立即上传
```

⚠️ 第 2 步到第 4 步之间同步会失败（预期中断），挑个不用 app 的空档做。

### 6）上线后建议验证的几条命令

```bash
# 数据目录不可被直接下载（应返回 403）
curl -I https://你的域名/sync/data/xiaojinku.json

# 非白名单来源不应回显 CORS 头
curl -sI -H 'Origin: https://evil.example.com' https://你的域名/sync/api.php | grep -i 'access-control-allow-origin'
# 期望：无输出

# 服务器数据不含凭据
curl -s -H 'X-Sync-Token: 你的令牌' https://你的域名/sync/api.php | grep -c 'pinHash\|"sync"'
# 期望：0

# 并发安全自测（会真实写入，先备份数据文件）
php /root/myapp/xiaojinku/app/deploy/concurrency_test.php \
    https://你的域名/sync/api.php 你的令牌
# 期望：RESULT: PASS
```
