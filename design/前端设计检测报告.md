| 维度 | 评级 | 一句话 |
|---|---|---|
| 工程质量 | **A−** | 分层清晰、纯函数沉淀扎实、行情容错到位、无 console 残留 |

## 一、可访问性（本次最重磅的发现）

### 1.1 对比度实测（浅色主题 · WCAG 2.1）

| 用途 | 前景 / 背景 | 实测 | 判定 |
|---|---|---|---|
| 正文 text / bg | `#2e2c33` / `#f6f3ee` | 12.45 | 通过 |
| **次要文字 text-sub / card** | `#7c7884` / `#ffffff` | **4.31** | 未达 4.5（临界） |
| **次要文字 text-sub / bg** | `#7c7884` / `#f6f3ee` | **3.89** | 未达标 |
| **微弱文字 text-faint / card** | `#aaa6b0` / `#ffffff` | **2.39** | **严重不达标** |
| **微弱文字 text-faint / bg** | `#aaa6b0` / `#f6f3ee` | **2.16** | **严重不达标** |
| **白字 / 主色按钮** | `#ffffff` / `#5fa896` | **2.79** | **不达标** |
| 导航选中 accent-strong / accent-soft | `#3d7266` / `#e7f1ed` | 4.79 | 通过 |
| **支出色 / card** | `#ec9a8e` / `#ffffff` | **2.19** | **严重不达标** |
| **收入色 / card** | `#7cc6a6` / `#ffffff` | **2.00** | **严重不达标** |
| **信用色 / card** | `#c3a3df` / `#ffffff` | **2.18** | **严重不达标** |
| 危险色 / card | `#e5736b` / `#ffffff` | 3.00 | 仅大字可用 |

**为什么这是真问题而不是吹毛求疵：**

- `text-faint`（2.16–2.39）用在**每一笔流水的时间戳、资金来源、底栏未选中标签、卡片副信息**——这是列表里出现频率最高的文字，2.16 意味着在户外光线下基本看不清
- 支出色 2.19 / 收入色 2.00 用在**金额**上——金额是这个 app 的核心内容，比正文还重要，却是最看不清的
- 主色按钮上的白字 2.79 → 所有"保存/确认"按钮

**暗色主题反而全部通过**（正文 13.05、次要 7.03、支出 7.77、收入 8.75），只有 `text-faint` 3.76 属大字可用。说明问题只出在浅色主题这一组色值上——把浅色的 `--text-faint` / `--expense` / `--income` / `--credit` 各加深一档即可，改动仅限 `index.css` 的变量定义，风险极低。

### 1.2 其他可访问性问题

| 问题 | 落点 | 影响 |
|---|---|---|
| **禁用缩放** | `index.html:5` `maximum-scale=1.0, user-scalable=no` | 违反 WCAG 1.4.4；弱视用户无法放大页面 |
| **无全局焦点样式** | `index.css` 仅 `.input:focus` 有描边，button/chip/列表行均无 `:focus-visible` | 键盘与外接键盘用户看不到当前焦点位置 |
| 触摸目标偏小 | `.chip` padding 8/14 + 13px 字 ≈ **34px**；`.seg-item` ≈ 35px；`.nav-link` ≈ 38px；删除按钮 `p-2` ≈ **32px** | 低于 44×44 基准，手指点击易误触 |
| 硬编码 `bg-white` | `LockScreen.tsx:19` | **暗色模式下锁屏是白底**，夜间解锁刺眼（真实体验 bug） |
| 硬编码 `slate-400 / slate-100` | `Modal.tsx:29/36`、`Money.tsx:32`、`LoadingScreen.tsx:3` | 绕过主题变量；`Money` 的折算金额（≈¥xxx）在浅色下约 2.6，不达标 |

## 二、设计系统

**做得好的部分（不要动）：**
- CSS 变量语义化完整（19 个浅色 + 19 个暗色变量），组件代码几乎不硬编码颜色（仅 8 处例外，已列在上表）
- 主色鼠尾草绿 `#5fa896` + 暖奶油底 `#f6f3ee`，方向明确且自洽，符合"自然有机 / 治愈系"
- `tabular-nums`（`font-feature-settings: 'tnum'`）已全局启用 → 金额数字对齐，专业
- 圆角（14/20/26）、阴影两级（soft / soft-sm）、安全区适配（`env(safe-area-inset-bottom)`）齐全

**需要注意：**
- 字阶未变量化：字号散落在各页面（`text-2xl`、`text-[15px]`、`text-[11px]`），无统一 scale
- 间距原子化到 Tailwind 类，但没有语义间距变量（卡片间距 `space-y-4` 靠记忆保持一致）

## 三、动效（用户已确认接受现状，仅作记录）

全站 **8 处** CSS transition，全部是 hover / active / focus 的即时反馈，**没有入场序列、没有页面过渡、没有列表错峰**。`prefers-reduced-motion` 未处理（但因为几乎没有动效，影响有限）。

按反 AI 味清单这属于"动效缺失"，但**用户已明确否决动效类改动**（页面切换动效、骨架屏均判定"没必要"），此处仅记录不提议。

## 五、工程质量（全栈视角）

**优点：**
- **分层干净**：`lib/calc.ts` 沉淀 22 个纯函数（净资产、持仓推导、批次配对、摊销、汇率折算），页面只做组装与格式化，业务逻辑未散落到视图层
- **行情容错到位**：`quoteService.ts` 有 `AbortController` + 双超时 + 东财/腾讯双源 fallback，失败静默降级而非崩溃
- **凭据不做明文存储**：`pin.ts` 存哈希而非明文，且注释诚实标注了算法强度
- 无 `console.log` 残留；TS `strict: true`

**待改进：**
- `any` **19 处**（含 `as any`），主要集中在列表渲染与事件处理
- `noUnusedLocals / noUnusedParameters` 均为 `false`，死代码不会被编译拦截
- **组件复用率低**：只有 `Modal`（6 处）、`EChart`（2 处）、`ConfirmDialog`（1 处）被复用；日常流水页与投资记录页各写各的行渲染，改一处要改两处
- 凭据哈希是 **djb2**（`pin.ts` 自注"演示用弱哈希"）→ 本地 4–6 位 PIN 可被瞬间枚举。但攻击者在能读 IndexedDB 的前提下锁本身已无意义，**风险可接受**，若要加固可换 Web Crypto PBKDF2 + 盐
- 产物单文件 **845 KB**（gzip 后约 272 KB），ECharts 已按需引入，属合理范围
